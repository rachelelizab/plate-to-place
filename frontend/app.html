Problem, design and analysis

Plate2Place: kinetic priorities with time-dependent routing

The problem

Every night, Bengaluru's restaurants, wedding halls, hostels and canteens discard cooked food while shelters nearby go short. Rescue groups coordinate on WhatsApp: a volunteer sees a post and goes, with no idea whether the food will still be safe on arrival, or whether someone else is already on the way. Cooked food is safe for only a few hours, and the same trip can take 15 minutes at 22:30 and 50 at 19:00.

Why the usual approaches fall short

  • First come, first served ignores distance and freshness, so volunteers cross the city for food that spoils before they arrive.
  • Nearest first ignores value and deadline, so a 250-portion wedding surplus can spoil while volunteers collect 15-portion posts.
  • Both use static priorities. The real priority of a post changes every minute.

The approach

Donation posted→HashMap registry→Kinetic heap (value decays)+AVL (expiry index)→Candidates→Time-dependent Dijkstra, both legs→Feasible? best meals per minute→HashMap claim lock

A donation of P portions with safe life L expiring at E has value f(t) = P·(E − t)/L, which is linear in time. The kinetic heap stores one certificate per parent–child edge (“parent ≥ child”) and the exact time it will fail. Only failures cost work.

Algorithm 1 · Kinetic heap advance

procedure ADVANCE(t)
  while events.min().time ≤ t do        // events = indexed min-heap of certificates
    (c, τ) ← events.pop();  now ← τ
    p ← ⌊(c − 1)/2⌋
    if fH[c](now) > fH[p](now) then
      swap H[c], H[p]
      RECOMPUTE certificates of p, c, and their children   // O(1) certs, O(log n) each
  now ← t

function FAILTIME(p, c)                     // when does f_c overtake f_p ?
  if bp ≤ bc then return ∞
  return (ap − ac) / (bp − bc)

Algorithm 2 · Choosing a pickup for an idle volunteer

function CHOOSE(v, t)
  KH.ADVANCE(t);  AVL.SWEEP(t)                          // drop expired posts
  C ← KH.TOPK(16) ∪ AVL.RANGE(t, t + 90)                // valuable ∪ urgent
  C ← { d ∈ C : not CLAIMED[d] }                         // HashMap lock
  arrive ← TD-DIJKSTRA(source = v.node, depart = t, targets = C)
  best ← none
  for each d in C do
    load ← min(v.capacity, d.remaining)
    eta  ← TD-DIJKSTRA-TO-NEAREST-SHELTER(d.node, arrive[d] + pickup, load) + drop
    if eta > d.expiry − margin then continue       // would spoil: never send anyone
    score ← load / (eta − t) × (1 + 0.6·max(0, 1 − slack/90))
    best ← argmax(best, score)
  CLAIMED[best] ← v;  return best

Algorithm 3 · Time-dependent Dijkstra

function TD-DIJKSTRA(sources, targets)
  arrive[·] ← ∞;  for (s, t0) in sources: arrive[s] ← t0; PQ.push(t0, s)
  while PQ not empty do
    (t, u) ← PQ.pop();  if done[u] then continue;  done[u] ← true
    if u ∈ targets and all targets settled then break
    for each edge (u, w) do
      t' ← t + base(u,w) × congestion(class, zone, t)    // cost depends on departure time
      if t' < arrive[w] then arrive[w] ← t'; PQ.push(t', w)
// Exact because congestion changes slowly enough that leaving later never arrives earlier (FIFO).

One dispatch decision costs O(log n + k) to gather candidates plus O(K·(V + E) log V) for the routes, where K ≤ 16 + (posts expiring within 90 minutes). A naive ranker that re-sorts every post every minute costs O(n log n) per minute whether or not anything changed; the kinetic heap only pays for the e crossings that actually happen.
